# Проверка Mira Media Downloader 1.4.4 «Минимализм»

Это план приёмки, а не отчёт о пройденных проверках. Результаты и итоговое число тестов относятся к отдельному отчёту QA конкретной сборки.

Для 1.4.3 проверить настоящий многоразмерный ICO и одинаковый AppUserModelID
у публичного запуска, основного окна и ярлыков Windows. Каждое собственное
модальное окно должно открываться по центру родителя; фон размывается и
затемняется только в памяти и восстанавливается при Apply/Cancel/Escape/close.
Проверить вложенные окна и перемещение родителя, светлую/тёмную темы,
разный масштаб и границы рабочей области монитора. Меню и всплывающий календарь
должны оставаться привязаны к кнопке/полю, без модального размытия.

В заголовке не должно быть повторной плашки состояния задания: актуальный
этап, прогресс и счётчики находятся в рабочей области. Проверить естественное
«Поиск изображений» и соответствующие подписи English/简体中文. Крестик очистки
QLineEdit проверить по пикселям в обеих темах при реальном DPI Windows, после
смены темы и при LTR/RTL. Нативные clear/edit/undo/read-only/disabled должны
сохранять поведение Qt; общие отступы кнопок не должны сдвигать встроенный значок.

Для 1.4.2 отдельно проверить облачко на раннем индикаторе в обеих темах и трёх
языках, передачу готовности после первой отрисовки и единственный публичный EXE
в основной папке. Запуск worker, встроенный браузер и установщик должны работать
с Core и библиотеками в `runtime`.

Регрессия Pixiv: после успешного входа автоматическая проверка должна включать
«Сохранить вход» на `/en/`, странице автора и в настройках. Кнопка должна
повторно проверять аккаунт перед сохранением. Гость, повреждённый ответ, таймаут,
смена cookies, переход страницы и запоздалый ответ не должны сохранять сессию.
Проверять готовый EXE на созданной тестовой сессии с полностью заблокированной
сетью; тестовый cookie не отправлять платформе. Реальный вход проверять отдельно
самим владельцем аккаунта.

## Исходное подтверждение и остающиеся границы

- Пользователь сообщил, что встроенный вход и скачивание X в 1.2.0 работают. Это пользовательское свидетельство; агент не вводил данные его аккаунта и не выполнял от его имени авторизованный обход.
- Предварительный публичный запрос Pixiv-профиля `20151243` вернул 99 ID публикаций. В этой проверке оригиналы не скачивались. Число ID нельзя записывать как число найденных/скачанных изображений.
- В отдельной ограниченной проверке исходного движка без авторизации для этого профиля сохранены две PNG-страницы одной работы 2424×4096, всего 5 690 583 байта: найдено 2, скачано 2, ошибок 0. Второй обычный запуск «Только новые»: найдено 2, скачано 0, пропущено 2, ошибок 0. Лимит — первые две картинки; вся галерея не обходилась, личные cookies не читались. Это доказательство публичного скачивания и повторного пропуска на таком образце, не аккаунтной авторизации или полноты галереи.
- Пользователь сообщил, что скачивание Pixiv в 1.4.2 работает. Это пользовательское свидетельство, не агентская проверка его аккаунта и не доказательство полноты галереи. Расширенная приёмка аккаунтных сценариев остаётся отдельным этапом. Успех синтетических тестов, открытие формы входа и публичный список ID её не заменяют. Статус Pixiv остаётся экспериментальным.
- В отдельной проверке исходного приложения с публичной английской формой Pixiv отключение нативного Windows WebAuthn позволило закрыть окно и полностью завершить Qt с кодом 0. Данные аккаунта не вводились. Это подтверждение устранения наблюдавшегося зависания при завершении, а не тест авторизации; готовый EXE нужно проверить отдельно.

## Без личной сессии: исходники и имитированная сеть

1. Проверить нормализацию X/Twitter/Pixiv-ссылок, отказ посторонним доменам/вложенным адресам и числовую папку автора. Явный выбор Pixiv включает экспериментальный адаптер без второго флажка. Вставка корректной X/Pixiv-ссылки синхронизирует выбор платформы и вход; ручная смена платформы очищает только несовместимую ссылку, сохраняя папку/период. При смене имени X папка с тем же ID не меняется.
2. Проверить несколько изображений X-поста и несколько страниц иллюстрации/манги Pixiv. Счётчик увеличивается для каждого допустимого изображения, а не для каждого ID публикации. Повтор ID не дублирует элемент; SHA-256 предотвращает второй файл с тем же содержимым. Pixiv использует только `urls.original`; отсутствие оригинала не вызывает загрузку миниатюры. Ugoira/видео пропускаются.

   Проверить основную кнопку «Найти и скачать» без предварительного подсчёта: один проход начинает сохранение по мере нахождения, счётчик растёт до завершения. Дополнительная «Найти и посчитать» не загружает оригиналы и не является обязательным этапом; последующий основной запуск — отдельное задание.
3. Проверить окно «Период загрузки»: исходное «Все даты», обе границы, только «С», только «По», одинаковый день, отказ началу позже конца и произвольному периоду без границ. Вся кнопка даты открывает календарь; выбор дня закрывает его, навигация по месяцам/годам и отмена не меняют выбранную дату. «Сегодня» использует UTC. Только «Применить» переносит изменения в главный экран; «Отмена», Escape и закрытие сохраняют прежние даты и подпись кнопки. Повторное открытие восстанавливает текущий выбор. Проверить границы UTC, включая метаданные с часовым поясом. Обе даты включены; отсутствующая/некорректная дата при активном фильтре не проходит.
4. Повторить «Только новые», восстановить один удалённый файл, проверить полный режим. Прервать сохранение и запустить заново: готовые файлы/история остаются, `.part` не считается готовым, незавершённый элемент скачивается заново.
5. Проверить паузу/продолжение/стоп перед запросами, в ожидании и между блоками файла. Не обещать мгновенную отмену уже ожидающего ответа: действуют тайм-ауты.
6. Проверить 401/403/429/5xx, ограниченные повторы, тайм-аут, повреждённое изображение и HTML вместо JPEG. Готовый ложный файл не появляется; журнал/UI показывают понятный итог без секретов.
7. Проверить синтетические профили Firefox/Chromium: метаданные обнаружения, явный выбор, read-only SQLite, фильтры платформы/имён/контейнера/срока, отсутствие записи и полного копирования базы. Отказ `v20`, недоступному ключу и занятой базе не приводит к обходу защиты, завершению браузера или скрытому анонимному запросу.
8. В изолированном `MIRA_SESSION_DIR` проверить DPAPI round-trip для X и Pixiv, отдельные имена/форматы/наборы cookies, совместимость сохранённого X 1.2.0 и отсутствие изменения одной сессии при сохранении/удалении другой. Проверить повреждённый, истёкший, слишком большой или неверной схемы vault, неверный домен/путь/secure. `.tmp` и основной файл содержат только ciphertext. Локальный выход удаляет точные файлы своей платформы и оставляет посторонние файлы.
9. Проверить явный выбор платформы и его синхронизацию со ссылкой, кнопки «Войти в X»/«Войти в Pixiv» и отдельные статусы. В «Дополнительно» доступны «Выйти из …», прежние источники браузер/файл/явный анонимный режим и интервалы запросов с прежними пределами. Отмена окна входа сохраняет старый vault. Настройки/история/файл задания/командная строка не содержат значений cookies; worker читает свой vault самостоятельно.
10. Проверить WebEngine off-the-record без storageName, MemoryHttpCache, NoPersistentCookies, ограничения HTTPS/main-frame по платформе, запрет попапов/загрузок, видимый текущий адрес без служебных параметров, отказ ошибкам TLS и сохранённый Chromium sandbox. Пароли/поля форм/2FA не читаются и не логируются. Для страниц входа запрашивается английский (`Accept-Language`, `lang=en`); это предпочтение сайта, а не обещание языка каждого его экрана. Нативное окружение окна следует выбранному языку и теме Mira, веб-страница сохраняет оформление сайта.

    В Windows проверить точечное отключение `WebAuthenticationUseNativeWinApi` до запуска WebEngine и сохранение существующего пользовательского списка отключений одним параметром. TLS, sandbox и встроенные ограничения Qt должны сохраняться. В помощи явно указано: пароль, ручные CAPTCHA/2FA; ключи доступа Windows Hello во встроенном окне не поддерживаются.
11. Проверить Pixiv-гостя отдельно: наличие даже корректного `PHPSESSID` без положительного серверного подтверждения не разрешает сохранение. Same-origin read-only `/ajax/user/extra?lang=en` работает на `/en/`, странице автора и настройках; результат в Python только boolean, без пароля, cookie, текста страницы или ID аккаунта. Проверить HTTP/content-type/origin/redirect, ограничение тела, таймаут и схему счётчиков. URL/cookie-change аннулирует прежний результат, устаревший callback игнорируется, сохранение требует нового успешного ответа. Неопознанный формат завершается отказом. X продолжает использовать свой отдельный набор cookies.
12. Перед авторизованной Pixiv-галереей проверить read-only `/ajax/user/extra` для embedded/browser/file. Гость, отсутствующий cookie, истёкшая сессия, HTTP-ошибка, HTML, неверный JSON и неверная структура дают ошибку входа **до** запроса списка публикаций. Нет анонимного продолжения/подмены источника. Явный `none` показывает ограничение доступа и не объявляет полный архив. Из ответа проверки не сохраняются сведения аккаунта.
13. Проверить «Настройки показа» и помощь: сначала пользователь настраивает видимость содержимого на официальном `https://www.pixiv.net/settings/viewing`, затем возвращается к проверке/сохранению входа и задаче Mira. Приложение само не меняет возраст, настройки отображения или доступ. CAPTCHA выполняется вручную в ограниченном виджете сайта; внешние аккаунтные страницы не разрешаются как обход.
14. Проверить меню Русский / English / 简体中文 и переключатель светлой/тёмной темы в заголовке: подписи, подсказки, окна, сообщения Mira и помощь меняются сразу; настройка восстанавливается после перезапуска. Смена языка/темы не меняет источник входа, каталог, ссылку и даты. Пути и данные не переводятся. Сохранённое неизвестное значение настройки безопасно возвращается к поддерживаемому варианту.
15. Проверить обе темы на реальных виджетах и снимках: основной/отключённый текст, основная кнопка, выбранные карточки и строки истории, журнал, меню, списки, календарь, поля ввода и фокус клавиатуры. Для текста проверить контраст, для собственноручно рисуемых значков/галочек — видимость в обеих темах. В «Дополнительно» выделенный текст интервала остаётся читаемым, ввод и крупные −/+ соблюдают границы. Проверить упрощённые китайские и длинные английские подписи при компактном окне и масштабировании.

## Собранный Windows-пакет

1. Запустить готовый EXE из целой распакованной папки. Проверить минимальное нативное окно: верхние параметры и запуск, три вкладки «Картинки»/«История»/«Журнал», отдельные окна периода и «Дополнительно». Значки X/Pixiv сопровождаются текстом; контурные кнопки читаемы и имеют подсказки. Проверить шрифты/Qt plugins, клавиатуру, компактное окно и масштабирование Windows без обрезанных действий, выбор каталога, локальные превью, историю и worker без консоли. Сохранённый вход X должен остаться совместимым при обновлении.
2. Отдельно проверить упакованные окна входа X/Pixiv и renderer: `QtWebEngineProcess.exe`, native dependencies, ресурсы, локали, корректное закрытие. Проверка локальной безопасной страницы подтверждает работу renderer, но не авторизацию на платформах.

   Проверить также закрытие публичной формы Pixiv без ввода данных: последовательно уничтожены view/page/profile, после закрытия работает интерфейс, весь проверочный процесс завершается с кодом 0 без принудительного выхода. Одного JSON-отчёта до завершения Qt недостаточно. На синтетическом подтверждённом входе проверить возврат Accepted после сохранения, а при отмене — Rejected; модальный вызов не должен завершаться раньше очистки WebEngine.
3. Прогнать синтетические DPAPI-сессии/Firefox-профили через упакованный worker без вывода cookie-значений. Проверить отсутствие секретов в логах/отчёте/настройках.
4. Проверить переносимый ZIP, единый установщик EXE, состав MiraMediaDownloader.exe/runtime/README/ROADMAP/LICENSE/лицензии и исходники. Установка/запуск/удаление под обычным пользователем не требуют Python, сети или прав администратора. Проверить manifest/SHA-256, уведомления PySide6/WebEngine/Chromium/PyCryptodomex, отсутствие личных cookies, vault и библиотеки `.mira` в поставке. Проверить наличие Qt-переводов и нужных локалей WebEngine, китайские глифы и переключение языка/темы после установки и в переносимом варианте.
5. При подготовке GitHub сверить тег и полный состав исходного архива, включая assets/native/scripts/tests, лицензионные уведомления и закреплённые зависимости. Не переносить cookies, DPAPI-vault, БД истории, логи и локальные QA-выводы. `.gitignore` не удаляет уже отслеживаемые секреты; просмотреть staged-файлы и историю отдельно. Наличие LICENSE/notices не закрывает нерешённые вопросы GPLv2-only/Apache-2.0 и соответствующих исходников из `GITHUB_PUBLISHING.md`; публикацию не объявлять юридически проверенной на основании GUI/worker-тестов.

## С собственной авторизацией пользователя

1. Для X повторить вход/задачу после обновления и восстановление прежней X-сессии. Сравнить известный небольшой диапазон дат и пост с несколькими изображениями. Отделять новое наблюдение от прежнего пользовательского подтверждения 1.2.0; не утверждать полноту всей истории автора.
2. Для Pixiv **сначала** на сайте проверить настройки отображения в том же аккаунте и возможность открыть выбранные работы. Соблюдать возрастные ограничения и правила аккаунта. В Mira выбрать экспериментальную платформу Pixiv, вставить ссылку автора, нажать «Войти в Pixiv», выполнить обычный вход/проверки, при необходимости открыть «Настройки показа», затем «Проверить вход» и «Сохранить вход».
3. Сравнить небольшой известный набор Pixiv-работ с несколькими страницами: количество отдельных оригиналов, разрешение, содержимое и папку `Pixiv/<ID автора>/`. Проверить пропуск ugoira и недоступных оригиналов с журналом. Записать, какие работы сайт реально предоставил аккаунту; не считать список публичных ID доказательством доступа к оригиналам.
4. Перезапустить приложение, повторить задание, проверить даты, «Только новые», паузу/стоп/продолжение. Проверить истечение/отзыв сессии: авторизованное задание должно остановиться с предложением войти заново. При выходе из Pixiv сохранённый X остаётся, и наоборот. Локальный выход не объявляется серверным отзывом.
5. При желании проверить свой браузер/Netscape-файл как дополнительные источники обеих платформ. Для Chromium `v20` ожидается понятный отказ без обхода; это не успешный импорт.

До фактического выполнения отмечать эти пункты невыполненными. Не включать пароли, cookies, vault или частные сведения аккаунта в доказательства проверки. Следующие этапы после приёмки Pixiv перечислены в `ROADMAP.md`.


Для публичной 1.4.4 дополнительно: фактические Python/Qt версии совпадают с
манифестом; Virtual Keyboard отсутствует; Qt/Chromium notices побайтно совпадают
с соответствующими исходниками; оба source-архива присутствуют в релизе,
полностью распаковываются и имеют опубликованные SHA-256. Установщик и portable
проверяются после новой сборки, в том числе встроенный renderer и Pixiv Save.
